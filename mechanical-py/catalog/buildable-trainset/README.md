# Generated buildable trainset artifacts

This folder is generated by:

```bash
scripts/buildable-trainset.sh
```

The manifest starts the buildable rolling-stock product structure:
fabricated parts, external components, subassemblies, assemblies, and
the final trainset. Generated definitions and travelers now carry
structured material specs, process specs, evidence requirements, and
inspection controls. The review calls out what is already solid in the
current basic design and what must be closed before first steel cut.

## How to use this folder

| If you are… | Start with | Then use |
|---|---|---|
| Design authority | [`current-design-buildability-review.md`](current-design-buildability-review.md) | Close yellow/red findings before release |
| Manufacturing engineer | [`buildable-trainset-manifest.md`](buildable-trainset-manifest.md) | Turn `MAKE` definitions into controlled drawings, fixtures, and NC/cut data |
| Train configuration engineer | [`train-end-interface.md`](train-end-interface.md) | Select panoramic glass outer ends or the optional mid open train-to-train connection on the common end interface |
| Long-consist planner | [`full-set-3train-assembly.md`](full-set-3train-assembly.md) | Review the worked 3-train / 9-car full-set example, parts, assembly steps, FreeCAD targets, and FEM matrix |
| Production planner | [`critical-path.md`](critical-path.md) | Plan parallel part fabrication, subassembly release, final train assembly, space use, and rough labour |
| Mass-properties engineer | [`mass-budget.md`](mass-budget.md) | Replace estimates by weighed, CAD-derived, or supplier-frozen category values |
| Assembly engineer | [`joint-control-schedule.md`](joint-control-schedule.md) | Close each joint with its named torque authority and interface drawing |
| Buyer / supplier manager | [`definitions/index.md`](definitions/index.md) | Turn `BID`/`SOURCE` definitions into RFQs and evidence requirements |
| Shop lead | [`travelers/index.md`](travelers/index.md) | Assign work centers, fill approvals/signatures during a real build |
| QA / inspector | [`travelers/index.md`](travelers/index.md) | Use QA gates, hold points, signoff blocks, and NCR/deviation logs |

The intended sequence is:

1. Read the buildability review for release blockers.
2. Use the manifest to understand the parent/child assembly tree.
3. Use `train-end-interface.md` to confirm whether each end position is
   dressed as a panoramic glass front/end or an open mid-train
   train-to-train connection.
4. Use `full-set-3train-assembly.md` only when planning the optional
   three-module / nine-car full-set worked example.
5. Use definitions as the drawing/RFQ/material/process source of truth.
6. Use the critical path to reserve the long final assembly track only
   for accepted subassemblies and keep steel, GFRP, bogie, HV, and
   interior kit work off-line where possible.
7. Close the mass budget and joint-control rows as supplier and drawing
   evidence becomes available.
8. Use travelers as the shop-routing, material/process-control, and QA
   template.
9. Attach real inspection evidence and signatures only during an
   authorised build.

`definitions/` is the generated definition pack. It contains JSON and
Markdown files for every product-tree node:

- `parts/` — fabricated parts plus BID/SOURCE external components.
- `subassemblies/` — reusable build cells such as underframe, roof,
  HV, bogie, and interior subassemblies.
- `assemblies/` — complete car, end, articulation, and control
  assemblies.
- `trainsets/` — final trainset-level definition.

Use `definitions/index.md` as the drawing/RFQ worklist. These files are
not stamped shop drawings; they are the traceable seed for the v2A
drawing, supplier-freeze, material/process-control, and proof-evidence
packages.

`travelers/` is the generated shop-traveler pack. It contains JSON and
Markdown traveler templates for every product-tree node. Each traveler
includes:

- document revision and pending approval blocks,
- material specifications, process specifications, and evidence
  requirements,
- estimated labor by operation,
- work centers and tooling IDs,
- QA gates linked to the component/assembly acceptance checks,
- operator, cell-lead, quality, and manufacturing-engineering signoff
  blocks,
- a nonconformance/deviation log.

These are signable manufacturing templates, not already-signed release
records. A real build cell must fill the approval/signature fields and
attach actual inspection evidence before first-article release.
