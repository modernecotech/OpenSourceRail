# Generated buildable trainset artifacts

This folder is generated by:

```bash
tools/automation/buildable-trainset.sh
```

The manifest starts the buildable rolling-stock product structure:
fabricated parts, external components, subassemblies, assemblies, and
the final trainset. Generated definitions and travelers now carry
structured material specs, process specs, evidence requirements, and
inspection controls. The review calls out what is already solid in the
current basic design and what must be closed before first steel cut.

The intended sequence is:

1. Read the buildability review for release blockers.
2. Use the manifest to understand the 101-part / 26-assembly tree, then use
   `supplier-anchors.md` to buy an anchor family or qualify a local equivalent.
3. Use `train-end-interface.md` to confirm whether each end position is
   dressed as a panoramic glass front/end or an open mid-train
   train-to-train connection.
4. Use definitions as the drawing/RFQ/material/process source of truth.
5. Use the critical path to reserve the long final assembly track only
   for accepted subassemblies and keep steel, GFRP, bogie, HV, and
   interior kit work off-line where possible.
6. Use `factory-plan.md` to reserve about 3,515 m2 of enclosed pilot
   factory, 2,200 m2 of yard/test apron, and the rough machinery package
   before lease/building work or RFQs start.
7. Use `trainset-build-cost.md` for the current rough-order build cost:
   direct material/supplier modules plus explicit labour at USD 10/h,
   with a 20% unexpected-cost premium. Its direct-module bucket already
   includes seats, floors, grab rails, interior lighting, roof HVAC,
   windows, side doors, sill/emergency kits, and panoramic end glass.
8. Qualify the small-component rail/fastener samples and close each
   fixture, lighting, door and glazing release gate in
   `small-component-standard.md`.
9. Close the mass budget and joint-control rows as supplier and drawing
   evidence becomes available.
10. Use travelers as the shop-routing, material/process-control, and QA
   template.
11. Attach real inspection evidence and signatures only during an
   authorised build.

`definitions/` is the generated definition pack. It contains JSON and
Markdown files for every product-tree node:

- `parts/` — fabricated parts plus BID/SOURCE external components.
- `subassemblies/` — reusable build cells such as underframe, roof,
  HV, bogie, and interior subassemblies.
- `assemblies/` — complete car, end, articulation, and control
  assemblies.
- `trainsets/` — final trainset-level definition.

Use `definitions/index.md` as the drawing/RFQ worklist. These files are
not stamped shop drawings; they are the traceable seed for the v2A
drawing, supplier-freeze, material/process-control, and proof-evidence
packages.

`travelers/` is the generated shop-traveler pack. It contains JSON and
Markdown traveler templates for every product-tree node. Each traveler
includes:

- document revision and pending approval blocks,
- material specifications, process specifications, and evidence
  requirements,
- estimated labor by operation,
- work centers and tooling IDs,
- QA gates linked to the component/assembly acceptance checks,
- operator, cell-lead, quality, and manufacturing-engineering signoff
  blocks,
- a nonconformance/deviation log.

These are signable manufacturing templates, not already-signed release
records. A real build cell must fill the approval/signature fields and
attach actual inspection evidence before first-article release.
