`93f7406d5ae0e948181f990d1074954db6234693`.

in this review. Historical source-bound archives remain untouched.

The host reported about 40 GB free. A full isolated checkout failed its

samples should use private run directories. The failed attempt left no new
candidate result. Before any native run, remeasure the configured 20 GiB host
reserve and all outstanding reservations; these numbers are only this review's

After verification, `cargo clean --target-dir` removed 2.0 GiB and 2.1 GiB
from two private Rust scratch targets. This reclaims temporary build output;
it does not shrink repository evidence or the later cold Arrow compile.

Coordinated railway runs now reserve projected writes on their actual output
filesystem before creating a contract directory. The policy retains a 20 GiB
free-space floor and projects 1 GiB for the aggregate, 512 MiB per requested
new bundle and 8 GiB per native job. Live OSR reservations share a locked
ledger; checkpoint checks and monitored subprocesses stop when the floor is
crossed. An unbounded 128-bundle request was held with 38 GiB free, while a
private Rust v2 test run completed under a 3 GiB reservation. This protects
cooperating OSR work; external writers and underestimated output can still
consume space. Held, failed and interrupted receipts remain visible, including
the admission reason when a run is refused.

In one coupled contract, `result.json` and an invocation JSON are about 688 MB
each, while stage and case directories occupy about 1.2 GB and 659 MB. The
campaign now uses one bounded canonical aggregate stream and projects motion
summaries without copying full trace arrays. On a 50,000-row synthetic motion
fixture, peak Python allocations fell from 14.3 MB to 0.21 MB with identical
canonical output. Case and stage writes now stream the same canonical bytes to
atomic pending files, preserving the last complete file on interruption. The
campaign still holds bodies, bundles, rows and the result
graph in memory. Native archive writers now stream tar members and gzip output
to atomic target files. A 16 MiB random-member fixture reduced peak Python
allocations from 83.9 MB to 0.38 MB with identical compressed bytes on this
host's Python 3.13. The member hashes and source helper are included in current
publication receipts; older published packets retain their own source epoch.

## Arrow and vectorisation boundary

The Rust `osr-campaign-columnar` tool uses [arrow-rs 60.1.0](https://github.com/apache/arrow-rs/releases/tag/60.1.0)
to build bounded, typed Parquet case indexes. It writes at most 128 rows per
batch and 512 rows or 16 MiB per part. A query reads selected columns and
verifies each matching backing case's SHA-256 and typed fields before returning
it. Missing installed mass remains null. The existing 112-case contract has
690,132,968 bytes of canonical case JSON; its derived Parquet part is 29,869
bytes. A debug-build index took 79.18 s and 15,400 KiB peak RSS, verification
77.86 s and 14,820 KiB, and a candidate query 1.73 s and 15,316 KiB. These
measurements are from one host and contract, not a general speedup claim.

The index is additive: it does **not** reduce retained case-file disk use.
Canonical JSON still carries heterogeneous physical graphs, exact identities
and historical evidence. Replacing those files requires a full typed schema,
round-trip and source-bound publication migration with all downstream readers;
deleting them now would break reproducibility. Dense raster arrays already use
compact typed Rust storage. Parallel reductions must preserve declared rounding
and identity rules.

The full migration needs typed per-domain stage schemas, a Parquet row core and
seven-stage reference table, and a Rust materializer that reconstructs each
heterogeneous row with identical `reused` flags and canonical `row_id`.
`railway_campaign.run`, cached-stage verification and publication must then
read the same source-bound dataset. The monolithic result and invocation files
also need replacement by a small manifest plus streamed rows. On the recorded
contract, zstd level 3 compresses 690,132,968 raw case bytes to 45,018,752
bytes and 1,208,872,620 raw stage bytes to 66,982,148 bytes; this is a
compression bound, not a Parquet size claim. A versioned v2 contract and
independent parity check are needed before retiring active JSON case storage.

An opt-in v2 preview now writes the typed row core and seven ordered stage
references for all 112 source cases into 27,201-byte and 41,971-byte Parquet
files. It records 784 stage references and nine still-untyped payload domains;
`replacement_admitted=false` is explicit. The direct debug binary took 89.25 s
and 101,832 KiB peak RSS for this contract. Repeated output hashes matched.
Source cases were read-only, and the 1.2 GiB private Cargo target was cleaned
after validation.

A separate Rust verification pass checked both Parquet schemas, every typed
value and null, 784 ordered stage references, each source case SHA-256, and
the preview file inventory against the same 112 cases. It completed in
91.50 s with 106,032 KiB peak RSS in its private run. Nested mass controls,
full stage requests and the nine named payload domains remain untyped; the
verifier does not admit JSON replacement.
