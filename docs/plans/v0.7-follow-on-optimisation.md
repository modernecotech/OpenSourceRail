# v0.7 follow-on runtime optimisation

This plan applies to the source-bound 112-bundle coupled packet and selected
wheel-supported reference at main `090ae689`. It changes publication and
launcher work, not the physical candidate, engineering obligations or native
solver results. Keep the 20 GiB cooperating-run disk floor and retain failed
and historical packets.

## Measured starting point

- The 721,570,214-byte active aggregate is authenticated, semantically
  projected and read for Arrow output in three complete case-shard passes.
  The latest full republish took about ten minutes and stayed below about
  0.75 GiB sampled Python RSS after its refinement preflight.
- `./osr build` took about six minutes. It rerenders the 156-page book after
  every selected packet rebuild, including changes outside the book's exact
  source set. A source-bound book check took under one second.
- The railway launcher asks for a 3 GiB Cargo-build reservation even when its
  Rust case codec is already built. Its current source identity omits three
  compiled Rust files and the workspace Cargo manifest, so it cannot safely
  authorize a build skip by itself.

## Ordered work

1. **Fuse publication authentication and semantic projection.** Use a strict
   publisher-local sink during the existing aggregate read, then keep the
   bounded Rust Arrow writer and independent packet verifier. Leave
   campaign-bound `aggregate_store.py` and current case/Parquet schemas
   unchanged. Preserve exact campaign, run, candidate and row identities.
2. **Reuse a verified book.** After selected publication, check the book's
   exact source and PDF receipt first. Render only when that check fails;
   retain the final selected seal and verifier. A book-only fast path can be
   considered separately with an explicit two-artifact rollback design.
3. **Avoid unnecessary Rust builds only with a post-build receipt.** Bind the
   executable bytes, all compiled local sources, Cargo manifests/lock,
   toolchain and relevant build flags. A missing or changed receipt takes the
   existing reserved-build path. The normal launcher remains offline.
4. **Measure and publish.** Run focused tamper and cache tests, compare exact
   active IDs, regenerate affected coupled and selected packets with their
   generators, check the 156-page book, inspect RSS and actual free space,
   then fast-forward main only after source-bound verification passes.

## Boundaries

Typed Arrow migration of further nested stage/ERP records needs a new typed
schema, exact reader/writer parity and a separate campaign source epoch. The
current canonical receipts and historical methods remain available for their
declared evidence. Tool substitutions remain candidate- and operation-bound;
the existing Code_Aster fallback and physical qualification holds are unchanged.

## Selected publication follow-on

The selected publisher now streams SHA-256 for linked files in 1 MiB chunks
and reuses hashes from authenticated linked packets within one source-map
construction. Its verifier performs the full linked check once through the
source map. Full builds perform one final seal after the PDF/receipt check and
keep the old selected packet and book pair available until final verification.
Late failures retain the attempted packet and restore the prior one. The
preflight runs before moving the old packet because supply and mass checks read
the selected cost export.

A book-only source change can now render to private staged PDF and receipt
paths. The path admits only an intact old book bound by a fully verified
selected packet. It changes only the two book hashes and manifest identity in
the selected manifest, checks the staged and installed book, and runs selected
verification again. A journal restores the three old files after an exception
or on the next build after interruption. An unknown live file hash becomes a
hold for inspection. `./osr book` goes through the selected build transaction
when a selected manifest exists; `./osr book --check` remains read-only.

The first full rebuild met a stale compact supply source binding because the
initial streaming digest change touched a shared source epoch. Moving the
bounded digest into the selected publisher kept all 43 supply hashes exact;
the compact supply packet and its evaluation were not rewritten. A second
attempt exposed preflight reading old selected cost exports after replacement;
moving preflight ahead of replacement resolved it. Both failed OSR runs have
receipts, and the failed selected attempt was retained. The successful
source-bound selected rebuild took **303.29 s**, versus **370.37 s** in the
previous warm pass, with **611,644 KiB** maximum RSS reported by GNU time.
Its selection and evaluation identities and all acceptance holds stayed
unchanged. A final regression and book-only path measurement follows this
code pass before merge.

The final source-bound full rebuild, including the preflight-order and disk
target regressions, passed in **302.19 s** with **594,716 KiB** maximum RSS.
Seventeen focused publication and book tests passed. A reversible
`docs/BOOK.md` change then exercised `./osr book` twice: the changed-source
refresh took **270.95 s**, and restoration took **270.32 s**. Both reported
`book_only=true`; each kept the selected source and payload maps, selection
and evaluation IDs exact. The chapter bytes were restored. The modest book
speedup reflects the two complete selected verifications around the staged
render. Any future scan reduction needs a new exact-byte integrity design;
stat-only reuse would weaken the present evidence contract.
