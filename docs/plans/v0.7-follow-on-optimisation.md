# v0.7 follow-on runtime optimisation

This plan applies to the source-bound 112-bundle coupled packet and selected
wheel-supported reference at main `090ae689`. It changes publication and
launcher work, not the physical candidate, engineering obligations or native
solver results. Keep the 20 GiB cooperating-run disk floor and retain failed
and historical packets.

## Measured starting point

- The 721,570,214-byte active aggregate is authenticated, semantically
  projected and read for Arrow output in three complete case-shard passes.
  The latest full republish took about ten minutes and stayed below about
  0.75 GiB sampled Python RSS after its refinement preflight.
- `./osr build` took about six minutes. It rerenders the 156-page book after
  every selected packet rebuild, including changes outside the book's exact
  source set. A source-bound book check took under one second.
- The railway launcher asks for a 3 GiB Cargo-build reservation even when its
  Rust case codec is already built. Its current source identity omits three
  compiled Rust files and the workspace Cargo manifest, so it cannot safely
  authorize a build skip by itself.

## Ordered work

1. **Fuse publication authentication and semantic projection.** Use a strict
   publisher-local sink during the existing aggregate read, then keep the
   bounded Rust Arrow writer and independent packet verifier. Leave
   campaign-bound `aggregate_store.py` and current case/Parquet schemas
   unchanged. Preserve exact campaign, run, candidate and row identities.
2. **Reuse a verified book.** After selected publication, check the book's
   exact source and PDF receipt first. Render only when that check fails;
   retain the final selected seal and verifier. A book-only fast path can be
   considered separately with an explicit two-artifact rollback design.
3. **Avoid unnecessary Rust builds only with a post-build receipt.** Bind the
   executable bytes, all compiled local sources, Cargo manifests/lock,
   toolchain and relevant build flags. A missing or changed receipt takes the
   existing reserved-build path. The normal launcher remains offline.
4. **Measure and publish.** Run focused tamper and cache tests, compare exact
   active IDs, regenerate affected coupled and selected packets with their
   generators, check the 156-page book, inspect RSS and actual free space,
   then fast-forward main only after source-bound verification passes.

## Boundaries

Typed Arrow migration of further nested stage/ERP records needs a new typed
schema, exact reader/writer parity and a separate campaign source epoch. The
current canonical receipts and historical methods remain available for their
declared evidence. Tool substitutions remain candidate- and operation-bound;
the existing Code_Aster fallback and physical qualification holds are unchanged.
