# Certification Release Gap Register

This register is the release-facing list of evidence still needed
before the current repository package can support a revenue-service
GoA 4 type-approval submission. It complements
[`evidence-status.md`](evidence-status.md): that page summarises
status by area; this page names the closure evidence expected for each
gap.

| Gap | Current in-tree state | Closure evidence |
|---|---|---|
| Independent safety assessment | Pre-submission pack is structured and traceable, but not assessor-reviewed | Named assessor review report, action log, and accepted residual-risk statement |
| Residual-risk acceptance | Hazards and mitigations are listed, but no national-authority threshold is applied | Deployment-specific ALARP / tolerability criterion signed by authority or assessor |
| Consensus refinement | TLA+ spec, Rust proptests and a documented abstraction/action map exist, but no machine-checked refinement proof connects them | Assessor-accepted refinement argument or tool-backed proof from `SMRaft.tla` to `osr-consensus` behavior |
| ATP bounded-proof completion | CI proves the fast expired-authority property; topology-heavy ATP harnesses exist but their full-run unwind bounds are not frozen release evidence | Review and freeze topology bounds and Kani/CBMC versions, complete every ATP harness without unwinding failures, and archive the reports |
| Interlocking bounded-proof completion | CI proves the movement-authority validity-window arithmetic; topology-heavy P1–P4 and whole-function P5 harnesses do not complete inside the hosted-runner limit and are not represented as a green CI gate | Refactor the proof model or freeze reviewed topology bounds, complete the full interlocking set without unwinding failures, and archive versioned reports |
| Safety-controller freeze | RP2350/Radxa pilot rigs are specified, while qualified safety-channel candidates and selection requirements are documented but not selected | Assessor-reviewed MCU/channel selection, safety manual and FMEDA inputs, common-cause analysis, frozen schematics and bench/HIL evidence |
| Signed safety-log deployment evidence | Authenticated consensus ingress/commit verification and simulator fault-injection tests reject forged, altered, replayed, stale/future, unknown-issuer, metadata-mismatched, and category-downgraded proposals | Frozen deployment key registry, secure-element provisioning/rotation procedure, production-transport capture, and hardware-in-the-loop evidence showing only verified entries reach state derivation |
| Pilot hardware integration evidence | RFC 0019 COTS/SBC path and board-level specs exist; controlled pilot integration evidence is not frozen | Exact SKU BOMs, wiring/harness maps, connector maps, enclosure/mounting notes, power/thermal margins, SD-card image checksums, bring-up logs, safety-net bench tests, and commissioning records |
| Custom-board release evidence | Custom boards are optional for a first pilot and required only when a deployment chooses OSR-specific carrier, power, safety-I/O, or sensor-interface boards; KiCad, gerbers, and board BOMs are not released | For any custom-board deployment: KiCad projects, gerber zips, board BOMs, bring-up logs, safety-net bench tests, and DFM/DFT review |
| Rolling-stock structural evidence | Nine CalculiX beam/space-frame screens and raw solver outputs cover chassis, bogie, body and articulation gross load paths. They are screening models, not production shell/solid FEA or physical correlation. | Released EN 15227 / EN 12663 / EN 13749 model and reports, convergence and weld/joint treatment, independent review, plus first-article proof/fatigue correlation and weld/NDT records |
| Door-system evidence | RFC 0023, build definitions and an IFE supplier-family anchor define the boundary; the exact cassette/order code and EN 14752 route remain open | Controlled supplier drawings/data, actuator/lock/obstruction/cycle/emergency/water tests, configuration record, notified-body route and vehicle integration tests |
| Obstacle/intrusion field evidence | Logic and simulations exist; no representative first-article sensor dataset | Calibration report, hot-weather/soiling/night/rain datasets, false-positive/false-negative analysis |
| Station charging and site energy | The tracked Samawah summary freezes eight passing full-day cases: separate and combined end-of-life battery/maximum-climate duty, reduced contacts, two consecutive unavailable charging stops, a late-running three-times-dwell shared-charger overlap, a ten-hour cabinet/pad outage and all-site grid outage. Overlapping/constrained requests and conservation errors are explicit evidence fields. | Re-run the matrix for each deployment timetable, then complete site solar yield, grid interconnect, charger thermal study, protection settings, train/charger interface tests and utility approval. |
| Operations validation | Rulebook is drafted in English | Operator workshop minutes, translated deployment rulebook where needed, competence/training records |
| LM3 first-article evidence control | All 81 unresolved product rows have controlled closure state and one or more routes through the 12-package [evidence register](../../design/component-catalogue/catalog/buildable-trainset/first-article-evidence-status.md). The [candidate register](../../design/component-catalogue/catalog/buildable-trainset/cots-candidates.md) covers all 56 bought-in rows with 41 official manufacturer/research options; the [execution pack](../../design/component-catalogue/catalog/buildable-trainset/first-article-execution-pack.md) defines the ordered RFQ/rig/test route. Zero physical/supplier packages are marked accepted. | Supplier responses and accountable submissions with exact configuration/procedure, calibrated equipment, raw artifacts and checksums, plus independent review and accepted work-package closure |

These are not code-style TODOs. They are release gates for the first
deployment package.
