# Automatic mapping: population, streets and traffic

Reviewed 11 October 2026. Baghdad now has a source-selected mapping evidence package alongside its retained 2020 access audit. The compact corridor planner uses native WorldPop Global2 2026 counts and reserves two additional investigation corridors for the northeast planning sector and two for the west, within the eight-line addition budget. It retains the original nine trunks and the original native 1.6/3/7 km density-dependent station settings. Sector reservations guide selection; they do not establish construction, walking access or operating acceptance.

## Executable integration

`refresh-city-mapping.py --city baghdad --fetch` downloads the explicitly selected sources, retains native bbox pixels, extracts the pedestrian graph and regenerates the comparison. `--check` reproduces the report offline and fails on altered pixels, graph, bbox, source selection or producer code. Fetching requires `rasterio` and `osmium`; the retained-data check uses NumPy/SciPy and does not require network access or OSM parsing. Country files are cached outside Git; only bounded city evidence is published.

The original 2020 evidence remains a separate dated source. It is never relabelled, its receipt is not rewritten to claim a newer epoch, and it still governs the existing catalogue access measure. Mapping reports expose all three source/epoch estimates. Native counts are summed once per catchment union and remain separate from smoothed routing scores, financial trips and fares.

The compact planner performs northeast, west and citywide phases, accounting for already-selected stop circles before subsequent gains. Sector-specific counts guide reserved phases, while the reported incremental gains are recomputed on the full selected population union. Candidate paths retain existing water, buildability, backtracking, ring-junction and route-length guards. The final emitted station inventory is checked independently; a priority cell is not proof that a native stop survived consolidation. Native synthesis retains the existing validated cost/demand/water/buildability routing grid. The new population source changes bounded corridor selection; it has not replaced every native station-density input or the complete road-cost raster. Fresh settlement/destination and routing-grid adoption requires its own reproducible regeneration.

The pedestrian screen uses shortest paths on actual OSM topology with a virtual station source preserving each station's own snap cost. Both station and population snaps are bounded at 150 m. These connections, entrances, sidewalks, access permissions and accessibility remain **unverified**. The screen never calls an arbitrary river-crossing snap an accepted connection. Border clipping can underestimate access, while missing restrictions and unsurveyed short snaps can overestimate it. A graph-access result is therefore neither a surveyed walkshed nor a lower-bound guarantee.

## Evidence needed for traffic-led routing

No verified open Baghdad road-level traffic counts, speeds or OD table were obtained in this review. The pipeline records these as unavailable. Road classes, building counts and synthetic SUMO flows cannot fill that evidence gap.

An eventual import must retain the observation time and interval, coordinate reference system, road/segment ID and direction, vehicle/person units, count versus speed classification, sample/confidence information, provenance and publication rights. Snap observations to a dated street network with explicit unmatched records. Keep peak/off-peak and weekday/weekend evidence separate; never convert road speeds directly into rail passengers. Household travel surveys, jobs, schools and actual transit demand are needed to justify mode share and fares.

Surveyed entrances and legal pedestrian crossings, administrative census boundaries, compatible 2024 small-area census records and traffic observations remain open inputs. Their absence does not prevent numerical planning, but it prevents claiming validated local access or demand.
